# Vunio 路线图

## 设计原则

所有决策按这六条取舍，冲突时靠前的优先。

1. **用平台，不造平台**：浏览器已有的能力（Custom Elements、Shadow DOM、ElementInternals、Web Animations）直接用，框架只补浏览器没有的部分。
2. **一次渲染，精确更新**：组件结构只创建一次；数据变化时只改动受影响的那个文字节点或属性。不用虚拟 DOM，不需要编译器。
3. **资源有主**：每个事件、计时器、动画、订阅都有归属，归属者消失时自动释放。泄漏应该是写不出来的，而不是靠自觉避免。
4. **设计即变量**：颜色、字体、形状、动效全部来自主题变量。组件只描述结构和行为，风格由主题决定。
5. **规范先于代码**：每个模块先有设计文档，组件先有规范。人和 AI 按同一份规范工作。
6. **零运行时依赖**：发布的代码不依赖任何第三方库；开发依赖只用于测试。

## 验收标准

### M1 响应式内核
- 提供 `signal`、`computed`、`effect`、`batch`、`untrack`、`createScope`
- 菱形依赖无毛刺：同一次变化中，effect 只运行一次，且看到的都是最新值
- computed 惰性求值、结果缓存；没人订阅时自动退订上游（不会造成泄漏）
- 循环依赖、effect 无限互相触发时抛出明确错误，而不是卡死页面
- 作用域可暂停 / 恢复 / 释放；恢复时只重新运行依赖确实变化过的 effect
- 组件属性本身就是响应式的，可以直接在 computed / effect / 模板中使用
- 纯逻辑部分可在 Node 中测试，覆盖率达到上述每一条

### M2 响应式模板
- 支持文字、属性（含多段插值）、布尔属性、DOM 属性、事件五种绑定位置
- 值可以是普通值、signal 或函数；只有用到 signal 的位置会订阅
- 同一模板再次渲染时复用 DOM，不重建
- `repeat` 带 key 的列表在增、删、重排时复用节点，移动次数最少（最长递增子序列）
- 条件分支切换时，旧分支里的订阅全部释放
- 插值永远不经过 `innerHTML`（`unsafeHTML` 除外），天然防 XSS
- 模板写错位置时（如在 `<textarea>` 内插值）给出中文错误信息，指出怎么改
- 组件移出页面时模板订阅暂停（不泄漏），移回时补上期间错过的变化

### M3 迁移
- 示例组件改用响应式模板，新增一个“响应式”演示（共享状态 + 列表）
- `COMPONENT_SPEC.md` 更新为新写法；README 同步

### M4 古风设计系统
- 先写设计文档 `docs/design/guofeng.md`：色板（含对比度）、字体、间距、形状、动效、纹理
- `themes/guofeng.css` 实现全部变量，昼 / 夜两套主题均满足 WCAG AA 对比度

### M5 效果
- 每个效果都尊重“减少动态效果”，离开视口自动暂停，高清屏不发虚

### M6 组件
- 每个组件按 `COMPONENT_SPEC.md` 自查清单逐条通过，并有浏览器测试
